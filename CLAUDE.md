# MyVector (`myvec`) — нотатки для агента

Повний опис команд, схеми й архітектури — у [README.md](README.md). Тут лише те, що не видно з коду і на чому вже обпікалися.

## Звідки що
- Рішення (грильня, 2026-11-03) з причинами: `~/.claude/plans/validated-sparking-lamport.md` на Mac, розділ «Рішення з грилю». Коротко: SQLite + sqlite-vec + FTS5, `embeddinggemma` 768d через Ollama, пам'ять — markdown у vault `~/MyVector/vault` (git, джерело істини), БД похідна (`myvec rebuild`).
- Вибір моделі й параметрів пошуку обґрунтований бенчмарком: [bench/REPORT.md](bench/REPORT.md). Не міняти модель/роутинг «на око» — переганяти `bench/` (`bench/README.md`).
- UI — дизайн-система Project-B (Geist, oklch-токени). Мова інтерфейсу — українська, числа `uk-UA`.
- Skill `/myvector`: [skill/myvector/SKILL.md](skill/myvector/SKILL.md) (встановлена копія — `~/.claude/skills/myvector/`; `install.sh` її оновлює).

## Машини
- Репозиторій: `https://github.com/Alexshl/myvector`. Встановлення/оновлення на будь-якій машині — `./install.sh`.
- Mac (launchd `com.myvec.serve`) і devbox (Ubuntu, `systemctl --user` `myvec.service`, linger). Індекс переноситься копіюванням `~/MyVector` + `myvec relocate` (README, «Перенесення на іншу машину»). Індекси на машинах далі живуть незалежно; vault (пам'ять) — окремий git-репо в `~/MyVector/vault`, без remote.
- devbox: без Ollama — ембеддинги через llama.cpp `llama-server` (`embed_api = "openai"`, `ollama_url = "http://127.0.0.1:11435"`, systemd user `embed-server.service`, файли в `contrib/llama-embed/`, README «Ембеддинги без Ollama»). CPU (RX 580 не підтримується ROCm) — первинна індексація великого проєкту там у рази повільніша; переносити індекс, а не будувати заново. Вектори Q8_0 збігаються з Ollama (cos 0,999), переембеджувати перенесений індекс не треба.
- `llama-server` **не обрізає** вхід > 2048 токенів (Ollama обрізав мовчки) — `OpenAIEmbedder` обрізає сам через `/tokenize`/`/detokenize`. Без цього sync падає на першому довгому чанку.

## Пастки
- **Оновлення:** завжди `uv tool install --reinstall --python 3.12 <repo>` (або `./install.sh`). Версія пакета не змінюється, без `--reinstall` uv мовчки ставить закешовану стару збірку. Після оновлення перезапустити демон (`myvec install-daemon` перезапускає).
- **Тести ніколи не чіпають справжні** `~/MyVector`, `~/.claude`, LaunchAgents/systemd, глобальний git config. Autouse-фікстура `env` у `tests/conftest.py` ставить `MYVEC_HOME` у tmp. **Не використовувати `monkeypatch.undo()`** — він знімає і цей патч, тест піде в справжній `~/MyVector` (так уже було з `sync.lock`). Повертати конкретний атрибут через `monkeypatch.setattr(..., real)`.
- **Секрети:** літеральні значення маскуються `•••`, шматок лишається; шматки з приватними ключами й відомими форматами токенів викидаються; `.env*`, `.dev.vars*`, `*password*`, `*secret*`, ключі, `*.sql` тощо не індексуються взагалі (`filters.py`). Нічого з цього не послаблювати; після змін фільтрів — проганяти скан БД на PEM/AKIA/токени.
- **Шум в індексі** (знайдено на розкатці 13 проєктів): SVG (158k шматків в одному проєкті — тепер у deny-list), секції «Community N» з `graphify-out/GRAPH_REPORT.md` (імпортуються лише Summary / God Nodes / Surprising Connections / Import Cycles / Knowledge Gaps), чужі клони й vendored-код (project-e: `exclude = ["third_party", "docs/research/src"]` у `.myvector.toml`). Перш ніж підключати новий проєкт — глянути, чи нема в ньому великих чужих дерев, і запропонувати `--exclude`.
- **Ранжування:** вектор — косинусна схожість × пом'якшена вага скоупу (`w_eff = 1 − 0.5·(1−w)`); гібрид — RRF, нормований на 2/61. RRF без нормування давав пласкі бали, і ваги скоупу перебивали схожість. `path_weight` (E8-20, ADR-048): ×0.8 для тестових code-хітів лише в `vector` без слова тесту; `doc_path_weight` (E8-21, ADR-049): ×0.9 для тікетів `docs/todo/**`, не діє для `kind=docs`, hybrid і запитів зі словом про доки (`mentions_docs`); новий шлях скорингу мусить множити так само, зміну - через `bench/live_eval.py`.
- **Відновлення сесій (`cm`, ADR-010):** текст відповіді ніколи в argv (видно в `ps`) - лише stdin (`cm send <id> -`). Enter не слати, коли на екрані діалог/permission prompt: `cm send` відмовляє кодом 4 - це `busy` (409), не обходити. `held` (сесію тримає термінал) визначати за точним session id у `ps`, не за cwd чи станом хуків: cwd дає хибні `held` для кількох сесій в одному проєкті.
- **UI моніторингу (E6-05):** `ui/monitor.js` має лишатися чистим, як `tracker.js` (лише `util.js`, без `fetch/document/window`; перевіряє `tests/test_monitor_js.py`), DOM-клей і графіки під виміряну ширину живуть в `app.js`. Команди `test_runs` маскуються ще раз на виході (`testruns._shape`), бо пасивне джерело писатиме cmdline: не прибирати. `running` рахується лише для цього хоста, чужі стають `lost`. Тестові БД, створені пререлізними збірками v7, можуть не мати колонки `interrupted` (лише dev) - пересоздати.
- **`src/myvec/ui/spend.js` має лишатися чистим**, як `monitor.js` (лише `util.js` і геометрія `monitor.js`, без `fetch/document/window`; перевіряє `tests/test_spend_js.py`); `tracker.js` лишається на одному імпорті, блок витрат картки вставляє `views.js` через `ui.cardExtra`.
- **`src/myvec/ui/adoption.js` чистий** (лише `util.js` + `spend.js`, перевіряє `tests/test_adoption_js.py`); payload `/api/search/usage` - лише агрегати (ADR-029, ADR-037), не додавати `q`/хеші/команди.
- **Метрика пошуку (E8-10, ADR-042):** чужу ОС відсікає `searchstats.FOREIGN_PREFIX` - тести беруть чужий cwd з нього, не хардкодом `/Users` (на Mac падатимуть). `onset` = мін(`registered_at`, перший myvec): `rebuild` ставить `registered_at` = час перебудови, самого його не вистачає. `resolve_project` не повинен падати назад на cwd для неіснуючого шляху.
- **`tool_calls.kind/doc` (E8-16, ADR-042):** у `tokens.db` лише літерали `searchkind.KINDS` і 0/1 (текст команди й шлях Read не зберігати). `searchkind` без звернень до ФС і використовує приватні функції `presearch` - це охороняє тест у `test_searchkind.py`; `search.DOC_EXTS` - реекспорт з `searchkind`, не копія. Міграція v3 робить повний дочит: доки він іде, підвид неповний. Read-only v2-БД дає `kind` NULL (`_tool_rows` перевіряє колонки), не нулі.
- **Стислий вивід пошуку (E8-13, ADR-043):** у не-tty `myvec search` стислий за замовчуванням (`--expand` повертає старий формат, скрипти - `--json`); CLI просить `compact`/`total` у `/api/cli/search`, без ехо `compact` (старий демон) іде прямим шляхом - після оновлення `myvec install-daemon`. `total in index` рахує лише збіги цілого слова/префікса (FTS), не infix - повнота за `rg`. Шаблон `search.md` описує цей вивід з E8-14 (ADR-045, `PROCESS_VERSION` 5; planner/reviewer пишуть у Log рядок `search:`); `search()`/скоринг не змінювати (bench).
- **Тривога CPU (ADR-018):** `load_alert_minutes` обмежується місткістю кільця (`720·load_sample_s/60 − 1`), інакше при малому `load_sample_s` тривога мовчки не спрацює; регресії тестів рахуються при читанні, не колонкою - не додавати схему.
- **`/api/status` (E6-11):** payload кешується ~3 с, статистика репо - окремим кешем; читання - read-only з'єднанням поза `db_lock`. Кожен новий POST, що міняє видиме в статусі, мусить викликати `invalidate_status()` (лічильник поколінь не дає загубити інвалідацію під час збирання).
- **`shared = false` (E8-05, ADR-030):** читається з маркера під час пошуку (`crossproject.is_shared`), не з БД; зіпсований маркер = прихований (fail-closed), не міняти на «спільний». Новий шлях пошуку по `scope=all` мусить передати `hidden`/поважати `respect_shared`; `respect_shared=False` лише для перегляду пам'яті в UI (інструмент власника).
- **`kind=docs` (E8-03, ADR-032):** будь-який новий шлях пошуку за `kind` мусить обробляти `docs` (`search.KINDS`, не копії кортежу); фільтр шляху - у KNN (`rowid IN`) і в FTS WHERE, не постфільтром, інакше доки тонуть у коді. Старий демон відхиляє `docs` - після оновлення `myvec install-daemon`.
- **Watcher на Linux (E6-12, ADR-033):** обрізаний обхід тримається на приватному API `watchdog` (`InotifyWatchGroup._add_all_callbacks`): пін `watchdog>=7.1,<8` у `pyproject` (`uv tool install` не читає `uv.lock`), тест-сторож атрибутів не прибирати. Не лишати `short_str` без виклику - repr усього `Watch` = мегабайтні рядки в `daemon.err.log` (фільтр `RuntimeWarning` за повідомленням). `max_queued_events` не збільшувати «на око»: overflow закриває debounced sync. `daemon.{err,out}.log` обрізає `logutil.cap_inplace` (truncate, не rename).
- **`myvec memory-audit` (E8-04, ADR-034):** лише `mode=ro` з'єднання (не `_open()`), без ембеддера/демона. Вивід `--candidates` (id + перший рядок) не потрапляє в тікети/логи/звіти - у звіт лише агрегати. Перший рядок спершу маскувати/ховати, потім обрізати (обрізка до маскування ріже токен і маска не спрацює).
- **`query_url` (E8-09, ADR-039):** сервер запитів мусить завантажувати той самий файл моделі, що й основний, інакше вектори розходяться мовчки. Fallback на `ollama_url` тихий - мертвий query-сервер видно лише як `embed query` ~2 с у `myvec search --debug`; `embed_docs` і запис пам'яті на `query_url` не слати.
- **`myvec forget-project` (E8-15, ADR-044):** не `forget` (він архівує пам'ять). Dry-run за замовчуванням, автоприбирання свідомо нема; `--missing` бере лише `gone`, порожній батько (імовірна точка монтування) = `unreachable`, його забувають лише явно; пам'ять/vault не чіпає.
- **Зупинка демона (E6-13):** відкритий SSE `/api/events` тримав uvicorn до 90 с SIGKILL. Сервер піднімати лише через `daemon.make_server` (не `uvicorn.run`): `handle_exit` виставляє `state.stopping`, `timeout_graceful_shutdown=3`; новий довгоживучий стрім мусить дивитись `state.stopping`. `TimeoutStopSec=15` діє після `myvec install-daemon`.
- **Відміна sync (E6-14):** довга робота в потоці executor демона мусить дивитись `state.stopping` / `SyncStats.cancel`, інакше atexit-join тримає процес до SIGKILL. uvicorn після lifespan перекидає SIGTERM (процес гине, потоки не join-яться), тому lifespan чекає sync до `SYNC_STOP_WAIT_S`=8 с (`wait_sync_stopped`): разом із `GRACEFUL_STOP_S` - у межах `TimeoutStopSec=15`. `SyncCancelled` кидати лише між COMMIT і BEGIN; новий `except Exception` на шляху sync мусить перекидати `SyncCancelled` (як `ModelMismatch`), інакше відміна стане «помилкою репо». `myvec sync` по Ctrl+C - код 130.
- **`cloud/` (E4-02, ADR-050):** `npm test` окремо від `uv run pytest -q` і послідовно (пам'ять devbox), сторож - `tests/test_cloud_static.py`; залежності лише точні версії, lock оновлювати `npx npm@11 install` (npm 10 падає), `npm ci` працює; `ACCESS_DEV_BYPASS` ніколи в `wrangler.toml` (лише `--var`/gitignored `.dev.vars`); у D1 лише хеші токенів, сирий токен - лише у файл `0600`; охорона `gen` живе всередині D1 `batch`, не в окремому SELECT.
- **Після великих видалень** (`gc`, зміна exclude) файл БД не зменшується: `myvec gc --vacuum` (2026-11-09: 4,2 → 2,2 ГБ).
- **`sync already running`** — lock тримає демон (він сам підхоплює нові активні проєкти в чергу). Не вбивати процеси демона/чужі — чекати.
- **`src/myvec/ui/tracker.js` має лишатися чистим** (дані -> html): без `fetch`, DOM, `location`, `localStorage`; посилання лише через переданий `hrefs`. Його перевикористає Worker (E4-04); чистоту перевіряє `tests/test_tracker_js.py`. node на devbox є лише в `~/.nvm`: запускати `PATH=$HOME/.nvm/versions/node/v22.23.4/bin:$PATH uv run pytest -q`, інакше node-тести скіпаються.
- **SubagentStart (E8-01, ADR-031):** контекст субагенту йде лише JSON-ом `hookSpecificOutput.additionalContext` (звичайний stdout не потрапляє); текст - фіксована константа `hooks.SEARCH_HINT`, без даних із БД/vault. Хук не підключений, доки власник не перезапустить `myvec install-hooks`.
- **`pre-search` (E8-11, ADR-040):** хук PreToolUse працює на кожен Bash - швидкий шлях без імпортів (`re.search` по тексту до `config`), класифікатор `presearch.py` чистий і stdlib; текст команди ніколи в лог (`_log` лише `type(e).__name__`), стан - два числа; чистку старого стану ґейтить mtime штампа `state/presearch/.pruned`, не теки (власний запис зсуває mtime теки). Glob і поле `if` свідомо не використані; хук не блокує. Не вмикається, доки власник не перезапустить `myvec install-hooks`.
- **Рядок «процес застарів» у SessionStart (E0-10, ADR-036):** хук імпортує `myvec.scaffold` (~27 мс) лише коли `.myvec/scaffold.json` існує; рядок без даних (числа й фіксований текст), команда/фраза - константи `UPDATE_CMD`/`UPDATE_PHRASE` у `problems.py` (єдине джерело). Вкладений підпроєкт (стан у корені репо) рядка/проблеми не має.
- **Hooks сесій:** лише stdlib, швидкі, завжди exit 0 (інакше гальмують Claude Code). Пульс (`session-pulse`) ніколи не міняє стан: паралельні tools ховали б справжнє «чекає». Після оновлення myvec власник має знову запустити `myvec install-hooks`, інакше нові hooks не підключені.
- **Семплер навантаження:** ціль < 1 % CPU. Не читати `cwd`/`cmdline` усіх процесів щотіку (≈ 2 %): лише `cpu_times`, `cwd` ліниво для процесів з ненульовою дельтою, раз на `(pid, create_time)`. Будь-який новий фоновий потік демона обов'язково покривати тестом, що проганяє `lifespan` з `background=True`.
- **Лог пошуків (ADR-029):** у `logs/searches.jsonl` ніколи не писати текст запиту (лише довжина/слова/прапорці/HMAC із `state/searchlog.salt`); шина й `queries.jsonl` пишуть `q` лише замаскованим. `tool_calls` у `tokens.db` - лише `cat`/`cwd`, без команди. Сесія в заголовок `X-Myvec-Session` - лише UUID. `tokens.db` v2 мігрує дочитом транскриптів (offset -> 0): не стирати `token_usage`.
- **Токени (ADR-013):** у `tokens.db` ніколи не зберігати текст транскриптів (лише білий список полів). Тести не читають справжні транскрипти: conftest знімає `CLAUDE_CONFIG_DIR` і ставить `MYVEC_CLAUDE_DIR`. `tokens.db` не відновлюється (Claude Code видаляє транскрипти через ~30 днів): бекапити разом із `~/MyVector`.
- `init --exclude` — кожен виключений шлях окремим `--exclude`. У zsh не передавати їх через одну змінну (`$ex` не розбивається на слова).
- **Тікети** (`docs/todo`, схема v5): таблиці `tickets*` похідні від файлів (джерело істини - git), `rebuild` їх відновлює; `status` у файлах міняє лише оркестратор, агенти - `myvec ticket log`. Тека в `.gitignore` не бачиться watcher - оновлюється раз на 5 хв. `init` відмовляє переписувати маркер з невідомим TOML (`MarkerRewriteRefused`) - не обходити, правити руками.
- **Inbox правок з UI (ADR-019):** пишемо лише через `inbox.write` (dir_fd + `O_NOFOLLOW`, `O_EXCL`, tmp + `os.link`; не `open(path)`). Тека `inbox/` поза індексом, sync і `fingerprint` (`.gitignore` з `*` + пропуск у `_on_fs_event`) - не додавати назад. «Оброблено» = файл зник; `inbox.py` лише stdlib + `tickets` (його читатимуть хуки E3-02).
- **Процес = рендер шаблонів (ADR-021):** `.claude/agents/*.md` і `.claude/rules/{workflow,tickets}.md` (англійською) - це байт-у-байт рендер `src/myvec/scaffold/templates/` за `tests/fixtures/scaffold/myvec.answers.json`; змінюєш процес - міняєш шаблон або слот у фікстурі, інакше `tests/test_scaffold_etalon.py` падає. Відповіді зі hard secret `myvec scaffold` відхиляє (код 2); шаблони їдуть у wheel як файли пакета; `.gitignore` проєкту дописується з `gitignore.fragment` (файл `.gitignore` у теці шаблонів не створювати).
- **`ticket migrate` (ADR-024):** `--fix` без `--write` нічого не пише; `--dir` лише всередині `--root` (`ticketmigrate.inside`, без симлінків) - не послаблювати, `--fix --write` чіпає файли проєкту. У тестах проєкти будувати в `tmp_path`, справжні (project-a тощо) лише читати. `ticket index --index-name` ім'я не зберігає (на теці з чужим `index.md` без прапорця відмова, код 2).
- **`scaffold --update` (E0-09, ADR-035):** текст для злиття і відбиток файла беруться з одного читання (`update._snap`), не читати файл двічі - інакше правка під час `merge-file` губиться. `merge3` ганяє `git merge-file` в ізольованому env (`GIT_CONFIG_GLOBAL`, `HOME` у tmp); `.bak-<ts>` лишаються в проєкті, `*.bak-*` не індексується (`filters.DENY_FILE_GLOBS`). Файли `mode: keep` зливаються як owned (E0-11, ADR-038): конфлікт блокує (код 3), відсутній keep-файл (власник не створював/видалив) автоматично не відтворюється, лише явним `--overwrite PATH`; не прибирати `base` для keep-записів у стані.
- **`scaffold` в наявній теці (ADR-023):** код 3 лише між plan і apply одного запуску, не між `--dry-run` і запуском; `--detect` читає тільки білий список і жоден компонент-симлінк - не розширювати.
- **`ticket lesson` (ADR-027):** лише через `inbox.write` з `kind="lesson"` (не писати файли inbox напряму); приватні шляхи (`/home/<u>`, `MyVector/vault`) відхиляються - не послаблювати `inbox._PRIVATE`. Текст уроку не потрапляє в рядок хука й вивід CLI.
- **`search.md` і `--adopt` (E8-17, ADR-046):** міняєш шаблон `search.md` - додай sha256 сирих байтів попереднього рендеру в `problems.SEARCH_RULE_OLD` і його текст у `tests/fixtures/scaffold/search_rule/vN.md`, інакше тест-сторож червоний, а розкатані файли лишаться `foreign`. Тексти старих версій у wheel не тримати.
- **`scaffold --adopt` (E8-12, ADR-041):** пише лише `.claude/rules/search.md` і ніколи стан (база з поточних файлів зробила б наступний `--update` перезаписувачем кастомних агентів); свій файл = `foreign`, `--overwrite` нема. Коди пошуку в `problems.py` лишаються stdlib без імпорту `myvec.scaffold`; бачать їх лише проєкти з текою тікетів.
- **Версія процесу (ADR-028):** змінив рендер (шаблон, дефолт слота, `_git_context`) - підніми `PROCESS_VERSION` і онови `tests/fixtures/scaffold/process_version.json`, інакше тест-сторож червоний. `.myvec/scaffold.json` пишеться лише в транзакції `apply`, `state.read` не має кидати; насінна група `docs/todo/<id>-<slug>/index.md` поза станом навмисно.
- **Нумерація ADR** призначає оркестратор (два planner-и паралельно взяли один номер).

- **`myvec measure`:** залежність `psutil` (ліниво, без неї піки `null`); модуль `measure.py` імпортується до typer — не тягнути в нього typer/sqlite-vec/httpx. Ніколи не пересилати SIGINT двічі: з tty Ctrl+C вже дійшов до всієї групи (перевірка `tcgetpgrp`), інакше дитина бачить два SIGINT. Хендлери ставити до `Popen`, SIGQUIT ігнорувати лише після нього.
- **Пасивні прогони (ADR-017):** npm перейменовує процес (`name()`=`npm test`, `cmdline`=`['npm test','','']`) - у класифікації першим словом і без порожніх токенів; у тестах моделювати саме так. Журнал `test_runs.jsonl` пишуть семплер і `measure` під `flock` (`.lock`), складач - `LOCK_EX` на rename.

## Перевірка змін
1. `uv run pytest -q` — усе зелене.
2. Перевстановити (`./install.sh` або команда вище), перезапустити демон.
3. Живий пошук у двох-трьох проєктах: запит природною мовою (uk/ru) і ідентифікатор; `--scope all` для крос-проєктного.
4. Для UI — відкрити http://127.0.0.1:7878 у Chrome (лише розширення Claude in Chrome), перевірити світлу/темну тему й вузьку ширину.

## Процес розробки

Деталі: `.claude/rules/workflow.md` (конвеєр, git, лінії) і `.claude/rules/tickets.md` (тікети). Агенти: `.claude/agents/`. Тікети: `docs/todo/` (`INDEX.md`), перевірка `uv run python scripts/tickets.py check`, індекс `... index`.

- Головна сесія — оркестратор: планує, вирішує, перевіряє за фактами (`git diff --stat`, вивід `uv run pytest -q`), решту делегує агентам. Конвеєр: planner → coder → tester → reviewer → docs-writer; баги: debugger → coder → tester; жива перевірка: qa. Дрібні правки без конвеєра.
- Git (гібрид): задачі конвеєра — гілка `t/<ticket-id>-<slug>` + PR на GitHub (у тілі шлях до тікета), дрібниці — прямо в `main`. Дві машини: `git pull` на початку, `git push` наприкінці.
- Паралельні лінії: до 2, у worktree `.worktrees/<ticket-id>`; створює й зливає лише оркестратор. Конвеєр тікета веде дочірня сесія, оркестратор бачить лише рядок статусу (ADR-026, розділ «Child session per ticket» у [orchestrator.md](skill/myvector/orchestrator.md)).
- Користувач затверджує лише план і дизайн UI; далі тікет іде автономно, PR окремо не схвалюються.
- Статус тікета міняє лише оркестратор. Агенти: effort не вище `medium`, Fable не використовувати, питання користувачу лише через `AskUserQuestion` (у саб-агентів його нема, питання повертає оркестратору).
- Секрети й реальний вміст `~/MyVector`/vault не копіювати в тікети, PR, логи й звіти агентів.
- Уроки й пастки: `docs/lessons.md` (читати першим); розділ «Пастки» вище лишається коротким переліком.
- **Економія контексту оркестратора:** політика (бриф 4 рядки, звіт ≤ 40 слів, тихі команди, поріг ~200 тис. → `docs/handoff.md`) - у [skill/myvector/orchestrator.md](skill/myvector/orchestrator.md); розмір контексту - `myvec tokens --session SID --context`. Уже розгорнуті проєкти отримають нові правила шаблонів лише після оновлення scaffold (E0-07).
